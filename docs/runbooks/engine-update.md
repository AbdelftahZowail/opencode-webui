# Runbook — when the engine / API changes

**Trigger:** a new opencode engine version, a route that 404s/400s, or a request
to "update the API stuff". Read `.opencode/release-helper.md`'s gotchas too.

The contract we track is the engine's `/openapi.json`. The snapshot lives at
`reference/openapi.json` (regenerated by script). `src/api/client.ts` +
`src/api/types.ts` are the hand-copied contract layer. `reference/coverage.md` is
the route map. The engine is **out of scope** — we adapt here, we never change it.

> **Snapshot is stale as of 2026-10-07.** Last real sync was `31aefe3`
> (2026-09-15, 116 → 123 paths) against **engine 2.0.3**. The live engine is
> **2.0.22**: 28 documented routes are gone, 21 live routes are undocumented, 88
> are modified (+24/−10 schemas). A block moved under `/api/experimental/*`
> (mcp, session import/stats/export/skill/wait, instructions, generate, config)
> and others were renamed (`revert/clear` → `DELETE /api/session/{id}/revert`;
> `vcs/branches` → `vcs/branch`; `form/request` → `/api/form`).
>
> **Several shipped features call moved routes** — the permission *rules* PUT,
> inbox steer/queue, form cancel/state, `vcs/branches`, export, wait. And the
> permission-reply **body** shape moved (`{reply}` → `{decision}`), which is the
> sharpest edge because a 400 is silent where a 404 is visible. Re-sync is
> **step 0 of any parity work** (`plans/parity.md` §2.0).

## Tooling (already fixed)

`fetch-openapi.ts` / `diff-openapi.ts` used to call `Service.ensure()`, whose
probe hits `/api/health` — a route the drifted engine no longer serves — so both
died with `TypeError: body is not an Object`. They now resolve the engine through
`server/engineDiscovery.ts` (`resolveEngineEndpoint`: spawn-free discovery first,
the registration fallback second, spawning `ensure()` only as a last resort).
The proxy uses the same module, so one method per concern.

## Steps

1. **Diagnose.** `bun run scripts/diff-openapi.ts` (pretty) — read `ONLY_LIVE`,
   `ONLY_SNAP`, `MODIFIED`, and the schema adds/removes. Confirm the engine
   version. Do not bundle the re-sync with an unrelated bug fix unless a route
   being fixed is the reason.
2. **Regenerate the snapshot.** `bun run scripts/fetch-openapi.ts` → review
   `git diff reference/openapi.json`. Never hand-edit the snapshot.
3. **Re-sync the client.** Update `src/api/client.ts` / `src/api/types.ts` for
   the moved/renamed routes (one function per endpoint, additive where possible).
   **Prefer the current route**; keep a legacy path/body fallback only where an
   old engine must still work (the pattern `exportSession` uses: current first,
   legacy on 404; the permission reply: current shape first, legacy field on a
   400/422).
4. **Re-verify the affected UI features against live**, on throwaway sessions —
   especially anything on a moved route: permission rules editor, inbox
   steer/queue, form cancel/state, export, wait, VCS branch/base.
5. **Rewrite `reference/coverage.md`** — every row is now suspect: route → client
   → UI, or client-only **with a reason**. Move removed routes to a dated
   "previous snapshot" note.
6. **Update the plan's ground truth.** `plans/parity.md` §2.0/§2.1 carry the
   engine version and drift; refresh them.
7. **Gates.** `bun run typecheck`, `bun run build`.
   `bun run scripts/diff-openapi.ts --check` must now exit 0 (it will exit 1
   until the re-sync lands — that is the point of the check in CI).

## Notes

- **A 404 is visible; a 400 is not.** When a path is unchanged but the body
  shape moved, the failure is silent — send the current shape and treat a
  400/422 as a signal to retry the legacy one.
- **The `{name}` vs `{command}` slash-command drift** is the canonical case:
  `api.runCommand` sends **both** `name` and `command` (+ the required `text`) so
  one request succeeds against either engine version (the engine ignores unknown
  body keys).
- **Don't trust the snapshot alone.** Read it as "what the client calls", not
  "what the engine currently serves", once drift exists.
- The versioned spec is also the `skills/webui/SKILL.md` contract reference — a
  contract change bumps the version and regenerates the skill
  (`runbooks/add-extension.md`).
